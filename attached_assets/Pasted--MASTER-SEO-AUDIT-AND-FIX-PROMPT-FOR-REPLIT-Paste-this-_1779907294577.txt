## D. THE STANDARD (WHAT EVERY PAGE MUST HAVE)

### D1. Meta tags

```html
<meta charset="UTF-8">
<meta name="viewport" content="width=device-width, initial-scale=1.0">

<title>[Primary Keyword] | [Secondary Benefit] | [Brand]</title>
<meta name="description" content="[150-160 chars, primary keyword in first 120 chars, value prop, soft CTA]">

<link rel="canonical" href="[absolute URL]">
<meta name="robots" content="index, follow, max-image-preview:large, max-snippet:-1, max-video-preview:-1">

<meta property="og:type" content="[website | article | product]">
<meta property="og:site_name" content="[SITE_NAME]">
<meta property="og:title" content="[title]">
<meta property="og:description" content="[description]">
<meta property="og:url" content="[absolute URL]">
<meta property="og:image" content="[1200x630 absolute URL]">
<meta property="og:image:width" content="1200">
<meta property="og:image:height" content="630">
<meta property="og:image:alt" content="[descriptive alt]">
<meta property="og:locale" content="en_US">

<meta name="twitter:card" content="summary_large_image">
<meta name="twitter:site" content="[TWITTER_HANDLE]">
<meta name="twitter:title" content="[title]">
<meta name="twitter:description" content="[description]">
<meta name="twitter:image" content="[absolute URL]">
<meta name="twitter:image:alt" content="[alt]">

<link rel="icon" type="image/svg+xml" href="/favicon.svg">
<link rel="icon" type="image/png" sizes="32x32" href="/favicon-32x32.png">
<link rel="apple-touch-icon" sizes="180x180" href="/apple-touch-icon.png">
<link rel="manifest" href="/site.webmanifest">
<meta name="theme-color" content="[brand hex from existing CSS]">
```

Rules: Title 50 to 60 chars, unique sitewide. Description 150 to 160 chars, unique sitewide. Canonical absolute and correct. OG image must exist and be 1200x630. No accidental noindex.

### D2. Headings
- One H1 per page, contains primary keyword, above the fold
- H2 for major sections (secondary keywords, question phrases)
- Strict hierarchy, no skipped levels
- Question-format H2s and H3s where natural

### D3. URLs
- Lowercase, hyphens, no underscores, no file extensions
- Short, descriptive, keyword-bearing
- Consistent trailing slash policy site-wide
- 301 (not 302) for permanent redirects
- Custom 404 page that returns 404 status

### D4. Images
- Descriptive filename
- Alt text describes image and includes keyword where natural (empty alt only for decorative)
- Explicit width and height attributes
- WebP or AVIF with fallback
- Hero under 500KB, others under 200KB
- Responsive srcset where used in multiple sizes
- `loading="lazy"` below the fold, `loading="eager"` and `fetchpriority="high"` on LCP image
- SVGs run through SVGO

### D5. Body content
- Primary keyword in first 100 words, in H1, in at least one H2
- Direct answer to the page's core question in the first paragraph (AEO and snippets)
- Minimum 800 words for service/product pages, 1500+ for cornerstone, 2000+ for ultimate guides
- Short paragraphs (2 to 4 sentences), Flesch reading ease 60+
- Bullet lists, numbered lists, comparison tables where appropriate
- TL;DR or summary box near top for long content
- FAQ section (4 to 8 questions) with FAQPage schema
- Visible publish date and last updated date

### D6. Internal linking
- At least 3 outbound internal links per page
- Every page receives at least 2 internal links from other pages (no orphans)
- Descriptive anchor text, never "click here"
- Breadcrumbs on every non-home page with BreadcrumbList schema
- Related posts/services module on every page
- Crawl depth 3 clicks or fewer from homepage

### D7. Structured data (JSON-LD)

Sitewide:
- Organization (homepage)
- WebSite with SearchAction (homepage)
- BreadcrumbList (every non-home page)

Page-specific:
- LocalBusiness or subtype for local pages
- Service for service pages
- Product for product pages
- Article or BlogPosting for blog posts
- FAQPage for FAQ sections
- HowTo for tutorial content
- VideoObject for videos
- RealEstateListing for property listings
- Review and AggregateRating where applicable

Every schema must validate in Google's Rich Results Test.

### D8. Speed and Core Web Vitals
Targets: PageSpeed 95+ mobile and desktop, LCP under 2.0s, INP under 200ms, CLS under 0.1, TTFB under 600ms.

- WebP/AVIF images with explicit dimensions
- Critical CSS inlined, non-critical deferred
- Preload hero image, primary font, critical CSS
- Preconnect to third-party origins
- Self-hosted fonts with `font-display: swap`, WOFF2 subset
- Minified CSS, JS, HTML
- Deferred or async non-critical JS
- Code splitting for heavy components
- Brotli or gzip compression
- Long cache headers with content hashing
- HTTP/2 or HTTP/3
- No render-blocking third-party scripts above the fold
- Layout shift reservations for ads, embeds, dynamic content

### D9. Technical foundation
- HTTPS with HSTS, all HTTP redirects to HTTPS
- `sitemap.xml` references all indexable URLs, listed in `robots.txt`
- `robots.txt` allows CSS/JS/images, blocks admin and search result pages
- No duplicate content
- Mobile-first responsive, touch targets 48x48px minimum
- Semantic HTML5
- Accessibility: aria-labels, input labels, skip-to-content link
- SEO-critical content rendered server-side, not pure CSR

### D10. AEO / GEO
- Question-format headings with direct answers immediately below
- Specific numbers, dates, names, stats in answers
- Outbound citations to authoritative sources
- Visible author bio and credentials (E-E-A-T)
- Visible datePublished and dateModified
- Definition-style content for key terms
- Comparison tables for "vs" queries
- Key Takeaways box at top of long content
- No critical answers hidden behind tabs, accordions, or JS-rendered content

### D11. Local SEO (if applicable)
- NAP in footer of every page, matching Google Business Profile
- LocalBusiness schema with geo coords, hours, priceRange, areaServed
- Embedded map on contact page
- Location-specific landing pages with unique content

## E. FIX PROTOCOL (NON-NEGOTIABLE)

1. **Preserve content**: never delete copy, headings, or media unless replacing duplicates or fixing a defect
2. **Preserve design**: do not change fonts, colors, spacing, or layout. SEO fixes happen in head, alt, schema, semantics, and code structure, not visual design. If a fix requires a visual change (e.g. converting a styled `<div>` to a real `<h1>`), flag it and propose minimal-impact CSS to preserve appearance
3. **One commit per page or per defect type**: never bundle unrelated fixes. Format: `SEO: [page] - [defect fixed]`
4. **Test after every change**: page renders, no console errors, no broken links, layout intact on desktop and mobile, integrations still work
5. **Reversible edits**: minimal diffs only, no refactors disguised as SEO fixes
6. **Ask before destructive changes**: deleting routes, changing URL slugs, removing shared components, modifying layouts that affect many pages. Propose, never assume
7. **Redirects required for URL changes**: any slug change ships with a 301 redirect from the old URL
8. **Update sitemap after any URL change**
9. **Update internal links after any URL change**: search the codebase for the old URL and update every reference
10. **Re-validate after every fix**: re-run the page-level checklist
